The VIV-32 instruction set is provisional in v0.1. This chapter defines the architectural meaning of each instruction. Opcode assignments and binary layouts are defined separately by the instruction encoding and opcode map.

\section{Instruction Notation}

\begin{itemize}
\item \(rd\): destination general-purpose register.
\item \(rd0\): first destination general-purpose register.
\item \(rd1\): second destination general-purpose register.
\item \(ra\): first source general-purpose register.
\item \(rb\): second source general-purpose register.
\item \(rs\): source general-purpose register.
\item \(imm\): immediate value encoded in the instruction.
\item \(offset\): signed PC-relative or base-relative offset.
\item \PC: program counter.
\item \SR: processor status register.
\item \flagN: negative flag.
\item \flagZ: zero flag.
\item \flagC: carry flag.
\item \flagV: overflow flag.
\item \flagE: arithmetic error flag.
\end{itemize}

\subsection{Assignment Notation}

\begin{itemize}
\item The notation \ensuremath{rd \assign x} means that value \(x\) is written to register \(rd\).
\item The notation \ensuremath{\PC \assign x} means that execution continues from address \(x\).
\item The notation \mem{x} means memory at address \(x\).
\item The notation \sext{x} means sign-extension of \(x\) to 32 bits.
\item The notation \zext{x} means zero-extension of \(x\) to 32 bits.
\item The notation \(x:y\) means a register pair, with \(x\) holding the low 32 bits and \(y\) holding the high 32 bits unless otherwise specified.
\end{itemize}

\subsection{Immediate Values}

\begin{itemize}
\item Unless otherwise specified, immediate operands are sign-extended to 32 bits before use.
\item Arithmetic immediate instructions sign-extend their immediate operands.
\item Logical immediate instructions zero-extend their immediate operands.
\item Shift counts are interpreted as unsigned values.
\item Bit indexes are interpreted as unsigned values in the range 0--31.
\end{itemize}

\section{Conditional Suffixes}

\begin{itemize}
\item Conditional instruction mnemonics use a dot-separated condition suffix.
\item Register-comparison branches use the form \code{b.<cond>}.
\item Flag-based branches use the form \code{bf.<cond>}.
\item Future conditional instructions should use the same suffix convention.
\end{itemize}

\begin{center}
\begin{tabular}{lll}

Suffix & Meaning & Basis \\
\hline
\code{.eq}  & equal / zero & \ensuremath{\flagZ = 1} \\
\code{.ne}  & not equal / non-zero & \ensuremath{\flagZ = 0} \\

\code{.le}  & signed less than or equal & signed comparison \\
\code{.gt}  & signed greater than & signed comparison \\
\code{.ge}  & signed greater than or equal & signed comparison \\
\code{.ltu} & unsigned less than & unsigned comparison \\
\code{.leu} & unsigned less than or equal & unsigned comparison \\
\code{.gtu} & unsigned greater than & unsigned comparison \\
\code{.geu} & unsigned greater than or equal & unsigned comparison \\
\code{.cs}  & carry set & \ensuremath{\flagC = 1} \\
\code{.cc}  & carry clear & \ensuremath{\flagC = 0} \\

\section{Flag Behaviour}

\begin{itemize}
\item Arithmetic and logical instructions update condition flags by default.
\item Comparison instructions update condition flags without storing a result.
\item Load and store instructions do not update condition flags.
\item Branch, jump, call, and return instructions do not update condition flags.
\item System instructions update condition flags only when explicitly specified.
\end{itemize}

\subsection{Negative Flag}

\begin{itemize}
\item The negative flag \flagN\ is set when the result of a flag-setting operation has bit 31 set.
\item The negative flag \flagN\ is cleared when the result has bit 31 clear.
\end{itemize}

\subsection{Zero Flag}

\begin{itemize}
\item The zero flag \flagZ\ is set when the result of a flag-setting operation is zero.
\item The zero flag \flagZ\ is cleared when the result is non-zero.
\end{itemize}

\subsection{Carry Flag}

\begin{itemize}
\item For addition, the carry flag \flagC\ is set when the operation produces an unsigned carry out of bit 31.
\item For subtraction, the carry flag \flagC\ is set when no unsigned borrow is required.
\item For subtraction, the carry flag \flagC\ is cleared when an unsigned borrow is required.
\item For logical operations, the carry flag \flagC\ is cleared unless otherwise specified.
\end{itemize}

\subsection{Overflow Flag}

\begin{itemize}
\item The overflow flag \flagV\ is set when a signed arithmetic operation overflows the signed 32-bit two's complement range.
\item The overflow flag \flagV\ is cleared when no signed overflow occurs.
\item For logical operations, the overflow flag \flagV\ is cleared unless otherwise specified.
\end{itemize}

\subsection{Arithmetic Error Flag}

\begin{itemize}
\item The arithmetic error flag \flagE\ is set when an arithmetic operation produces an exceptional condition that does not trap in VIV-32 v0.1.
\item Integer divide-by-zero sets \flagE.
\item Arithmetic instructions that complete normally clear \flagE, unless otherwise specified.
\end{itemize}

\section{Shift Instructions}

\subsection{Shift Carry Behaviour}

\begin{itemize}
  \item For shift instructions, \flagC\ receives the last bit shifted out when the shift count is non-zero.
  \item If the shift count is zero, \flagC\ is left unchanged.
  \item Shift instructions clear \flagV\ and \flagE.
  \item Shift instructions update \flagN\ and \flagZ\ from the final shifted result.
\end{itemize}

\subsection{\code{shl}}

\begin{itemize}
\item Syntax: \code{shl rd, ra, rb}
\item Operation: \ensuremath{rd \assign ra << (rb \bitand 31)}
\item Vacated low bits are filled with zero.
\item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
\item \flagC\ receives the last bit shifted out, if the shift count is non-zero.
\item \flagV\ is cleared.
\item \flagE\ is cleared.
\end{itemize}

\subsection{\code{shli}}

\begin{itemize}
\item Syntax: \code{shli rd, ra, imm}
\item Operation: \ensuremath{rd \assign ra << (imm \bitand 31)}
\item Vacated low bits are filled with zero.
\item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
\item \flagC\ receives the last bit shifted out, if the shift count is non-zero.
\item \flagV\ is cleared.
\item \flagE\ is cleared.
\end{itemize}

\subsection{\code{shr}}

\begin{itemize}
\item Syntax: \code{shr rd, ra, rb}
\item Operation: logical right shift, \ensuremath{rd \assign ra >> (rb \bitand 31)}
\item Vacated high bits are filled with zero.
\item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
\item \flagC\ receives the last bit shifted out, if the shift count is non-zero.
\item \flagV\ is cleared.
\item \flagE\ is cleared.
\end{itemize}

\subsection{\code{shri}}

\begin{itemize}
\item Syntax: \code{shri rd, ra, imm}

\item Vacated high bits are filled with zero.
\item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
\item \flagC\ receives the last bit shifted out, if the shift count is non-zero.
\item \flagV\ is cleared.
\item \flagE\ is cleared.
\end{itemize}

\subsection{\code{sar}}

\begin{itemize}
\item Syntax: \code{sar rd, ra, rb}
\item Operation: arithmetic right shift, \ensuremath{rd \assign ra >> (rb \bitand 31)}
\item Vacated high bits are filled with the original sign bit of (ra).
\item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.

\section{Multiply and Divide Instructions}

\subsection{\code{mul}}

\begin{itemize}
  \item Syntax: \code{mul rdlo, rdhi, ra, rb}
  \item Operation: signed 32-bit multiply.
  \item The operands \(ra\) and \(rb\) are interpreted as signed 32-bit two's complement integers.
  \item The full signed 64-bit product is computed.
  \item The low 32 bits of the product are written to \(rdlo\).
  \item The high 32 bits of the product are written to \(rdhi\).
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item \flagN\ is set from bit 31 of \(rdhi\).
  \item \flagZ\ is set if the full 64-bit product is zero.
  \item \flagC\ is cleared.
  \item \flagV\ is cleared.
  \item \flagE\ is cleared.
\end{itemize}

\subsection{\code{mulu}}

\begin{itemize}
  \item Syntax: \code{mulu rdlo, rdhi, ra, rb}
  \item Operation: unsigned 32-bit multiply.
  \item The operands \(ra\) and \(rb\) are interpreted as unsigned 32-bit integers.
  \item The full unsigned 64-bit product is computed.
  \item The low 32 bits of the product are written to \(rdlo\).
  \item The high 32 bits of the product are written to \(rdhi\).
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item \flagN\ is set from bit 31 of \(rdhi\).
  \item \flagZ\ is set if the full 64-bit product is zero.
  \item \flagC\ is cleared.
  \item \flagV\ is cleared.
  \item \flagE\ is cleared.
\end{itemize}

\subsection{\code{div}}

\begin{itemize}
  \item Syntax: \code{div rdq, rdr, ra, rb}
  \item Operation: signed 32-bit division.
  \item The operands \(ra\) and \(rb\) are interpreted as signed 32-bit two's complement integers.
  \item If \(rb\) is non-zero, the signed quotient is written to \(rdq\).
  \item If \(rb\) is non-zero, the signed remainder is written to \(rdr\).
  \item If \(rb\) is zero, \flagE\ is set.
  \item If \(rb\) is zero, \(rdq\) and \(rdr\) are left unchanged.
  \item Divide-by-zero does not trap in VIV-32 v0.1.
  \item If \(ra\) is \code{0x80000000} and \(rb\) is \code{0xFFFFFFFF}, signed division overflows.
  \item On signed division overflow, \flagE\ is set.
  \item On signed division overflow, \(rdq\) and \(rdr\) are left unchanged.
  \item Signed division overflow does not trap in VIV-32 v0.1.
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item On successful division, \flagN\ is set from bit 31 of the quotient.
  \item On successful division, \flagZ\ is set if the quotient is zero.
  \item On successful division, \flagC\ is cleared.
  \item On successful division, \flagV\ is cleared.
  \item On successful division, \flagE\ is cleared.
\end{itemize}

\subsection{\code{divu}}

\begin{itemize}
  \item Syntax: \code{divu rdq, rdr, ra, rb}
  \item Operation: unsigned 32-bit division.
  \item The operands \(ra\) and \(rb\) are interpreted as unsigned 32-bit integers.
  \item If \(rb\) is non-zero, the unsigned quotient is written to \(rdq\).
  \item If \(rb\) is non-zero, the unsigned remainder is written to \(rdr\).
  \item If \(rb\) is zero, \flagE\ is set.
  \item If \(rb\) is zero, \(rdq\) and \(rdr\) are left unchanged.
  \item Divide-by-zero does not trap in VIV-32 v0.1.
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item On successful division, \flagN\ is set from bit 31 of the quotient.
  \item On successful division, \flagZ\ is set if the quotient is zero.
  \item On successful division, \flagC\ is cleared.
  \item On successful division, \flagV\ is cleared.
  \item On successful division, \flagE\ is cleared.
\end{itemize}

\section{Load and Store Instructions}

Load and store instructions transfer data between general-purpose registers and memory. VIV-32 uses base-plus-offset addressing for ordinary memory access.

\subsection{Address Calculation}
\label{sec:load-store-address-calculation}

Load and store instructions use base-plus-offset addressing. The assembly syntax writes the address operand as:

\begin{center}
\code{offset(base)}
\end{center}

\noindent
In this syntax, \code{base} is a general-purpose register containing a 32-bit base address, and \code{offset} is the assembly-level representation of the encoded M-type \code{offset15} field.

\begin{itemize}
  \item The encoded offset field is the M-type \code{offset15} field.
  \item \code{offset15} is a signed 15-bit byte offset.
  \item The offset is sign-extended to 32 bits before address calculation.
  \item The effective address is a 32-bit byte address.
\end{itemize}

\noindent
The effective address is computed as:

\begin{center}
\ensuremath{addr \assign base + \sext{offset15}}
\end{center}

\noindent
The computed address is interpreted according to the access size of the instruction. Byte accesses may occur at any address. Halfword and word accesses are subject to the alignment rules defined below.

\subsection{Alignment}

\begin{itemize}
\item Byte loads and stores may access any address.
\item Halfword loads and stores must access a 2-byte aligned address.
\item Word loads and stores must access a 4-byte aligned address.
\item Misaligned halfword and word accesses raise a misaligned access exception.
\item On a misaligned access exception, \code{epc} receives the address of the faulting instruction.
\item On a misaligned access exception, \code{ecause} receives the misaligned access exception code.
\item On a misaligned access exception, \code{eaddr} receives the misaligned effective address.
\item The exception entry sequence is defined in the exceptions and interrupts chapter.
\end{itemize}

\subsection{Flag Behaviour}

\begin{itemize}
\item Load instructions do not update condition flags.
\item Store instructions do not update condition flags.
\end{itemize}

\subsection{\code{lb}}

\begin{itemize}
\item Syntax: \code{lb rd, offset(base)}
\item Operation: load signed byte.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item One byte is loaded from memory.
\item The loaded byte is sign-extended to 32 bits.
\item The sign-extended value is written to (rd).
\item No condition flags are updated.
\end{itemize}

\subsection{\code{lbu}}

\begin{itemize}
\item Syntax: \code{lbu rd, offset(base)}
\item Operation: load unsigned byte.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item One byte is loaded from memory.
\item The loaded byte is zero-extended to 32 bits.
\item The zero-extended value is written to (rd).
\item No condition flags are updated.
\end{itemize}

\subsection{\code{lh}}

\begin{itemize}
\item Syntax: \code{lh rd, offset(base)}
\item Operation: load signed halfword.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The effective address must be 2-byte aligned.
\item If the effective address is misaligned, a misaligned access exception is raised.
\item Two bytes are loaded from memory using big-endian byte order.
\item The loaded halfword is sign-extended to 32 bits.
\item The sign-extended value is written to (rd).
\item No condition flags are updated.
\end{itemize}

\subsection{\code{lhu}}

\begin{itemize}
\item Syntax: \code{lhu rd, offset(base)}
\item Operation: load unsigned halfword.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The effective address must be 2-byte aligned.
\item If the effective address is misaligned, a misaligned access exception is raised.
\item Two bytes are loaded from memory using big-endian byte order.
\item The loaded halfword is zero-extended to 32 bits.
\item The zero-extended value is written to (rd).
\item No condition flags are updated.
\end{itemize}

\subsection{\code{lw}}

\begin{itemize}
\item Syntax: \code{lw rd, offset(base)}
\item Operation: load word.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The effective address must be 4-byte aligned.
\item If the effective address is misaligned, a misaligned access exception is raised.
\item Four bytes are loaded from memory using big-endian byte order.
\item The loaded 32-bit word is written to (rd).
\item No condition flags are updated.
\end{itemize}

\subsection{\code{sb}}

\begin{itemize}
\item Syntax: \code{sb rs, offset(base)}
\item Operation: store byte.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The low 8 bits of (rs) are stored to memory.
\item Byte stores may access any address.
\item No condition flags are updated.
\end{itemize}

\subsection{\code{sh}}

\begin{itemize}
\item Syntax: \code{sh rs, offset(base)}
\item Operation: store halfword.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The effective address must be 2-byte aligned.
\item If the effective address is misaligned, a misaligned access exception is raised.
\item The low 16 bits of (rs) are stored to memory using big-endian byte order.
\item No condition flags are updated.
\end{itemize}

\subsection{\code{sw}}

\begin{itemize}
\item Syntax: \code{sw rs, offset(base)}
\item Operation: store word.
\item The effective address is computed as described in Section~\ref{sec:load-store-address-calculation}.
\item The effective address must be 4-byte aligned.
\item If the effective address is misaligned, a misaligned access exception is raised.
\item The full 32-bit value in (rs) is stored to memory using big-endian byte order.
\item No condition flags are updated.
\end{itemize}

\section{Constant Construction Instructions}

VIV-32 instructions are fixed-width 32-bit words. A single instruction cannot encode every possible 32-bit constant together with an opcode and register fields. Larger constants and addresses are therefore constructed using one or more instructions.

\subsection{\code{lui}}

\begin{itemize}
  \item Syntax: \code{lui rd, imm16}
  \item Operation: load upper immediate.
  \item The 16-bit immediate is placed in bits 31--16 of the result.
  \item Bits 15--0 of the result are cleared.
  \item Operation: \ensuremath{rd \assign imm16 \shleft 16}
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item \flagC, \flagV, and \flagE\ are cleared.
\end{itemize}

\subsection{\code{lli}}

\begin{itemize}
  \item Syntax: \code{lli rd, imm16}
  \item Operation: load lower immediate.
  \item The 16-bit immediate is zero-extended and written to \(rd\).
  \item Operation: \ensuremath{rd \assign \zext{imm16}}
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item \flagC, \flagV, and \flagE\ are cleared.
\end{itemize}

\subsection{\code{lhi}}

\begin{itemize}
  \item Syntax: \code{lhi rd, imm16}
  \item Operation: load upper immediate, preserve lower bytes.
  \item The 16-bit immediate is written to \code{rd} bits 31--16.
  \item Operation: \ensuremath{rd \assign (\zext{imm16} << 16) OR (rd AND 0xFFFF)}
  \item Updates flags: \flagN, \flagZ, \flagC, \flagV, \flagE.
  \item \flagC, \flagV, and \flagE\ are cleared.
\end{itemize}

\subsection{\code{lli} and \code{lhi} for Constant Construction}

The \code{lhi} instruction may be used after \code{lli} to construct a full 32-bit constant.

\subsection{Full-Width Constants}

\begin{itemize}
  \item The assembler should provide a pseudo-instruction for loading full-width constants.
  \item Recommended pseudo-instruction syntax: \code{li rd, imm32}
  \item The \code{li} pseudo-instruction expands to one or more real instructions.
  \item The exact expansion is defined by the assembler and relocation model.
\end{itemize}

\subsection{Address Constants}

\begin{itemize}
  \item The assembler should provide a pseudo-instruction for loading symbol addresses.
  \item Recommended pseudo-instruction syntax: \code{la rd, symbol}
  \item The \code{la} pseudo-instruction expands to relocation-aware constant construction instructions.
  \item The exact expansion is defined by the assembler, linker, and relocation model.
\end{itemize}

\section{Branch Instructions}

Branch instructions perform conditional PC-relative control transfer. VIV-32 defines two branch families:

\begin{itemize}
  \item register-comparison branches, which compare two registers directly;
  \item flag-based branches, which test the existing condition flags in \SR.
\end{itemize}

\subsection{Branch Target Calculation}

\begin{itemize}
  \item Branch offsets are signed PC-relative offsets.
  \item Branch offsets are measured in 32-bit instruction words.
  \item The encoded offset is shifted left by two bits to form a byte offset.
  \item The branch target is relative to the address of the instruction following the branch.
  \item Branch targets must be 4-byte aligned.
  \item Branch instructions do not update condition flags.
\end{itemize}

\subsection{Register-Comparison Branches}

Register-comparison branches compare \(ra\) and \(rb\) directly. They do not depend on the current condition flags.

\subsection{\code{b.eq}}

\begin{itemize}
  \item Syntax: \code{b.eq ra, rb, label}
  \item Operation: branch if \(ra = rb\).
  \item Signedness: not applicable.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.ne}}

\begin{itemize}
  \item Syntax: \code{b.ne ra, rb, label}
  \item Operation: branch if \(ra \ne rb\).
  \item Signedness: not applicable.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.lt}}

\begin{itemize}
  \item Syntax: \code{b.lt ra, rb, label}
  \item Operation: branch if \(ra < rb\), treating both operands as signed 32-bit two's complement integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.le}}

\begin{itemize}
  \item Syntax: \code{b.le ra, rb, label}
  \item Operation: branch if \(ra \le rb\), treating both operands as signed 32-bit two's complement integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.gt}}

\begin{itemize}
  \item Syntax: \code{b.gt ra, rb, label}
  \item Operation: branch if \(ra > rb\), treating both operands as signed 32-bit two's complement integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.ge}}

\begin{itemize}
  \item Syntax: \code{b.ge ra, rb, label}
  \item Operation: branch if \(ra \ge rb\), treating both operands as signed 32-bit two's complement integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.ltu}}

\begin{itemize}
  \item Syntax: \code{b.ltu ra, rb, label}
  \item Operation: branch if \(ra < rb\), treating both operands as unsigned 32-bit integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.leu}}

\begin{itemize}
  \item Syntax: \code{b.leu ra, rb, label}
  \item Operation: branch if \(ra \le rb\), treating both operands as unsigned 32-bit integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.gtu}}

\begin{itemize}
  \item Syntax: \code{b.gtu ra, rb, label}
  \item Operation: branch if \(ra > rb\), treating both operands as unsigned 32-bit integers.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{b.geu}}

\begin{itemize}
  \item Syntax: \code{b.geu ra, rb, label}
  \item Operation: branch if \(ra \ge rb\), treating both operands as unsigned 32-bit integers.
  \item Flags: not updated.
\end{itemize}

\subsection{Flag-Based Branches}

Flag-based branches test the current condition flags in \SR. They do not perform a new comparison.

\subsection{\code{bf.eq}}

\begin{itemize}
  \item Syntax: \code{bf.eq label}
  \item Operation: branch if \flagZ\ is set.
  \item Common use: branch if the previous flag-setting result was zero.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.ne}}

\begin{itemize}
  \item Syntax: \code{bf.ne label}
  \item Operation: branch if \flagZ\ is clear.
  \item Common use: branch if the previous flag-setting result was non-zero.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.cs}}

\begin{itemize}
  \item Syntax: \code{bf.cs label}
  \item Operation: branch if \flagC\ is set.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.cc}}

\begin{itemize}
  \item Syntax: \code{bf.cc label}
  \item Operation: branch if \flagC\ is clear.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.vs}}

\begin{itemize}
  \item Syntax: \code{bf.vs label}
  \item Operation: branch if \flagV\ is set.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.vc}}

\begin{itemize}
  \item Syntax: \code{bf.vc label}
  \item Operation: branch if \flagV\ is clear.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.es}}

\begin{itemize}
  \item Syntax: \code{bf.es label}
  \item Operation: branch if \flagE\ is set.
  \item Common use: branch after arithmetic operations that may set the arithmetic error flag.
  \item Flags: not updated.
\end{itemize}

\subsection{\code{bf.ec}}

\begin{itemize}
  \item Syntax: \code{bf.ec label}
  \item Operation: branch if \flagE\ is clear.
  \item Flags: not updated.
\end{itemize}

\subsection{Signed Flag-Based Comparisons}

After a \code{cmp} or \code{cmpi} instruction, signed comparison results may be tested using flag combinations.

\begin{center}
\begin{tabular}{lll}
\hline
Condition & Meaning & Flag test \\
\hline
\code{bf.lt} & signed less than & \ensuremath{\flagN \ne \flagV} \\
\code{bf.le} & signed less than or equal & \ensuremath{\flagZ = 1} or \ensuremath{\flagN \ne \flagV} \\
\code{bf.gt} & signed greater than & \ensuremath{\flagZ = 0} and \ensuremath{\flagN = \flagV} \\
\code{bf.ge} & signed greater than or equal & \ensuremath{\flagN = \flagV} \\
\hline
\end{tabular}
\end{center}

\begin{itemize}
  \item These mnemonics test the existing flags.
  \item They are most commonly used after \code{cmp} or \code{cmpi}.
  \item They do not perform a new comparison.
\end{itemize}

\subsection{Unsigned Flag-Based Comparisons}

After a \code{cmp} or \code{cmpi} instruction, unsigned comparison results may be tested using carry and zero flags.

\begin{center}
\begin{tabular}{lll}
\hline
Condition & Meaning & Flag test \\
\hline
\code{bf.ltu} & unsigned less than & \ensuremath{\flagC = 0} \\
\code{bf.leu} & unsigned less than or equal & \ensuremath{\flagC = 0} or \ensuremath{\flagZ = 1} \\
\code{bf.gtu} & unsigned greater than & \ensuremath{\flagC = 1} and \ensuremath{\flagZ = 0} \\
\code{bf.geu} & unsigned greater than or equal & \ensuremath{\flagC = 1} \\
\hline
\end{tabular}
\end{center}

\begin{itemize}
  \item These mnemonics test the existing flags.
  \item They are most commonly used after \code{cmp} or \code{cmpi}.
  \item They do not perform a new comparison.
\end{itemize}

\section{Jump and Call Instructions}

Jump and call instructions perform unconditional control transfer. Unlike branch instructions, jump and call instructions do not test condition flags or compare registers.

\subsection{Jump Target Rules}

\begin{itemize}
\item Jump and call targets are 32-bit instruction addresses.
\item Jump and call targets must be 4-byte aligned.
\item Attempting to jump or call to a misaligned address raises a misaligned instruction fetch exception.
\item Jump and call instructions do not update condition flags.
\end{itemize}

\subsection{\code{jmp}}

\begin{itemize}
\item Syntax: \code{jmp label}
\item Operation: PC-relative unconditional jump.
\item The encoded offset is measured in 32-bit instruction words.
\item The encoded offset is shifted left by two bits to form a byte offset.
\item The jump target is relative to the address of the instruction following the \code{jmp}.
\item Operation: \ensuremath{\PC \assign \PC + 4 + (\sext{offset} \shleft 2)}
\item No general-purpose register is modified.
\item No condition flags are updated.
\end{itemize}

\subsection{\code{call}}

\begin{itemize}
\item Syntax: \code{call label}
\item Operation: PC-relative call.
\item The return address is the address of the instruction following the \code{call}.
\item The return address is written to (r15), the architectural link register.
\item The encoded offset is measured in 32-bit instruction words.
\item The encoded offset is shifted left by two bits to form a byte offset.
\item The call target is relative to the address of the instruction following the \code{call}.
\item Operation: \ensuremath{r15 \assign \PC + 4}
\item Operation: \ensuremath{\PC \assign \PC + 4 + (\sext{offset} \shleft 2)}
\item No condition flags are updated.
\end{itemize}

\subsection{\code{jr}}

\begin{itemize}
\item Syntax: \code{jr target}
\item Operation: register-indirect unconditional jump.
\item The target register contains the destination address.
\item The destination address must be 4-byte aligned.
\item Operation: \ensuremath{\PC \assign target}
\item No general-purpose register is modified.
\item No condition flags are updated.
\end{itemize}

\subsection{\code{jalr}}

\begin{itemize}
\item Syntax: \code{jalr rd, target}
\item Operation: register-indirect call.
\item The target register contains the destination address.
\item The destination address must be 4-byte aligned.
\item The return address is the address of the instruction following the \code{jalr}.
\item The return address is written to (rd).
\item Operation: \ensuremath{rd \assign \PC + 4}
\item Operation: \ensuremath{\PC \assign target}
\item No condition flags are updated.
\end{itemize}

\subsection{Link Register Convention}

\begin{itemize}
\item The architectural link register is (r15).
\item The ABI name for (r15) is \code{lr}.
\item The \code{call} instruction always writes the return address to (r15).
\item The \code{jalr} instruction may write the return address to any general-purpose register.
\item ABI-conforming code should use (r15) as the standard link register unless there is a specific reason to use another register.
\end{itemize}

\subsection{\code{ret}}

\begin{itemize}
\item \code{ret} is an assembler pseudo-instruction, not a distinct architectural instruction in VIV-32 v0.1.
\item Syntax: \code{ret}
\item Expansion: \code{jr r15}
\item Operation: return to the address held in the link register.
\item No condition flags are updated.
\end{itemize}

\subsection{Nested Calls}

\begin{itemize}
\item A call instruction overwrites the link register.
\item A function that calls another function must save its incoming link register value if it needs to return to its own caller.
\item The ABI defines how functions save and restore the link register.
\end{itemize}

\section{System and Control Instructions}

System and control instructions provide access to processor control state, exception handling, interrupt control, and execution control.

\subsection{Control Registers}

\begin{itemize}
  \item VIV-32 defines a small set of architectural control registers.
  \item Control registers are accessed using \code{mrs} and \code{msr}.
  \item Access permissions are defined by the privilege model. In VIV-32 v0.1, only machine mode is defined.
\end{itemize}

\begin{center}
\begin{tabular}{lll}
\hline
Name & Meaning & Description \\
\hline
\code{pc}     & Program counter & Current instruction address \\
\code{sr}     & Status register & Condition flags and interrupt-enable state \\
\code{epc}    & Exception program counter & Address saved on exception entry \\
\code{ecause} & Exception cause & Cause code saved on exception entry \\
\code{eaddr}  & Exception address & Faulting address saved on relevant exceptions \\
\code{evbase} & Exception vector base & Base address for exception and interrupt vectors \\
\hline
\end{tabular}
\end{center}

\subsection{\code{nop}}

\begin{itemize}
  \item Syntax: \code{nop}
  \item Operation: no operation.
  \item Encoding: \code{0x00000000}.
  \item No general-purpose register is modified.
  \item No control register is modified.
  \item No condition flags are updated.
  \item Execution continues at the next instruction.
\end{itemize}

\subsection{\code{halt}}

\begin{itemize}
  \item Syntax: \code{halt}
  \item Operation: halt instruction execution.
  \item The processor stops executing instructions.
  \item The processor remains halted until reset or platform-defined external action.
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{trap}}

\begin{itemize}
  \item Syntax: \code{trap imm}
  \item Operation: raise a software trap exception.
  \item The immediate operand is encoded as the X-type \code{trapimm12} payload.
  \item On trap entry, \code{ecause} receives the software trap exception code.
  \item On trap entry, \code{epc} receives the address of the instruction following the \code{trap} instruction.
  \item On trap entry, \code{eaddr} receives zero.
  \item The trap immediate is not stored in \code{ecause}.
  \item Software may recover the trap immediate by decoding the \code{trap} instruction at \ensuremath{epc - 4}.
  \item The exception entry sequence is defined in the exceptions and interrupts chapter.
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{syscall}}

\begin{itemize}
  \item Syntax: \code{syscall}
  \item Operation: raise a system call exception.
  \item \code{syscall} is a distinct architectural instruction.
  \item \code{syscall} may share exception-entry machinery with \code{trap}.
  \item On syscall entry, \code{epc} receives the address of the instruction following the \code{syscall}.
  \item On syscall entry, \code{ecause} receives the system call exception code.
  \item The system call number and arguments are passed according to the ABI.
  \item The exception entry sequence is defined in the exceptions and interrupts chapter.
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{iret}}

\begin{itemize}
  \item Syntax: \code{iret}
  \item Operation: return from interrupt or exception.
  \item Execution resumes from the address stored in \code{epc}.
  \item Operation: \ensuremath{\PC \assign \code{epc}}
  \item The precise status-register restore behaviour is defined in the exceptions and interrupts chapter.
  \item No condition flags are updated, except as part of status-register restoration if defined.
\end{itemize}

\subsection{\code{ei}}

\begin{itemize}
  \item Syntax: \code{ei}
  \item Operation: enable maskable interrupts.
  \item The interrupt-enable bit in \code{sr} is set.
  \item No general-purpose register is modified.
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{di}}

\begin{itemize}
  \item Syntax: \code{di}
  \item Operation: disable maskable interrupts.
  \item The interrupt-enable bit in \code{sr} is cleared.
  \item No general-purpose register is modified.
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{rdpc}}

\begin{itemize}
  \item Syntax: \code{rdpc rd}
  \item Operation: read program counter.
  \item The address of the \code{rdpc} instruction is written to \(rd\).
  \item Operation: \ensuremath{rd \assign \PC}
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{mrs}}

\begin{itemize}
  \item Syntax: \code{mrs rd, cr}
  \item Operation: move from control register.
  \item The value of control register \code{cr} is written to \(rd\).
  \item No condition flags are updated.
\end{itemize}

\subsection{\code{msr}}

\begin{itemize}
  \item Syntax: \code{msr cr, rs}
  \item Operation: move to control register.
  \item The value of \(rs\) is written to control register \code{cr}.
  \item Writes to control registers may have immediate architectural effects.
  \item Writing \code{pc} using \code{msr} is not supported in VIV-32 v0.1.
  \item No condition flags are updated, except when writing \code{sr}.
\end{itemize}

\section{Pseudo-Instructions}

Pseudo-instructions are assembler conveniences. They do not necessarily correspond to distinct architectural instruction encodings. A conforming assembler may expand pseudo-instructions into one or more real VIV-32 instructions.

\subsection{Pseudo-Instruction Policy}

\begin{itemize}
  \item Pseudo-instructions are not part of the architectural instruction encoding unless explicitly stated otherwise.
  \item Pseudo-instructions may expand differently depending on immediate size, relocation requirements, or target address range.
  \item The assembler is responsible for selecting a correct expansion.
  \item The exact expansion rules are defined by the assembler and toolchain specification.
\end{itemize}

\subsection{\code{li}}

\begin{itemize}
  \item Syntax: \code{li rd, imm32}
  \item Operation: load a 32-bit immediate value into \(rd\).
  \item \code{li} is a pseudo-instruction.
  \item The assembler expands \code{li} into one or more constant-construction instructions.
  \item Possible expansions include:
  \begin{itemize}
    \item \code{lli rd, imm16}, when the value fits in 16 bits;
    \item \code{lui rd, upper16} followed by a lower-half construction instruction;
    \item a relocation-aware sequence when the value depends on linker resolution.
  \end{itemize}
\end{itemize}

\subsection{\code{la}}

\begin{itemize}
  \item Syntax: \code{la rd, symbol}
  \item Operation: load the address of \code{symbol} into \(rd\).
  \item \code{la} is a pseudo-instruction.
  \item The assembler expands \code{la} into relocation-aware address construction instructions.
  \item The final address may be resolved by the linker.
  \item The exact expansion is defined by the toolchain specification.
\end{itemize}

\subsection{\code{mov}}

\begin{itemize}
  \item Syntax: \code{mov rd, rs}
  \item Operation: copy the value of \(rs\) into \(rd\).
  \item \code{mov} is a pseudo-instruction.
  \item Recommended expansion: \code{addi rd, rs, 0}
  \item Since \code{addi} updates flags by default, assemblers may alternatively use a non-flag-setting move sequence if such an instruction is later defined.
\end{itemize}

\subsection{\code{clear}}

\begin{itemize}
  \item Syntax: \code{clear rd}
  \item Operation: write zero to \(rd\).
  \item \code{clear} is a pseudo-instruction.
  \item Recommended expansion: \code{addi rd, r0, 0}
  \item Since \code{addi} updates flags by default, \code{clear} also updates flags unless the assembler provides a non-flag-setting expansion.
\end{itemize}

\subsection{\code{ret}}

\begin{itemize}
  \item Syntax: \code{ret}
  \item Operation: return to the address stored in the link register.
  \item \code{ret} is a pseudo-instruction in VIV-32 v0.1.
  \item Expansion: \code{jr r15}
\end{itemize}

\subsection{\code{push}}

\begin{itemize}
  \item Syntax: \code{push rs}
  \item Operation: push a 32-bit register value onto the stack.
  \item \code{push} is a pseudo-instruction.
  \item The stack grows downward.
  \item Recommended expansion:
  \begin{verbatim}
addi sp, sp, -4
sw   rs, 0(sp)
  \end{verbatim}
  \item The expansion must preserve stack alignment requirements at public function call boundaries.
\end{itemize}

\subsection{\code{pop}}

\begin{itemize}
  \item Syntax: \code{pop rd}
  \item Operation: pop a 32-bit register value from the stack.
  \item \code{pop} is a pseudo-instruction.
  \item Recommended expansion:
  \begin{verbatim}
lw   rd, 0(sp)
addi sp, sp, 4
  \end{verbatim}
  \item The expansion must preserve stack alignment requirements at public function call boundaries.
\end{itemize}

\section{Reserved Instructions}

\begin{itemize}
  \item Instruction encodings not defined by VIV-32 v0.1 are reserved.
  \item Reserved encodings must not be generated by conforming assemblers.
  \item Reserved encodings are reserved for future architectural extensions, implementation-specific features, or debugging facilities.
  \item Executing a reserved encoding raises an illegal-instruction exception.
  \item On an illegal-instruction exception, \code{epc} receives the address of the illegal instruction.
  \item On an illegal-instruction exception, \code{ecause} receives the illegal-instruction exception code.
  \item If exception handling is unavailable, the machine halts.
\end{itemize}

\section{Instruction Set Status}

\begin{itemize}
  \item The VIV-32 v0.1 instruction set is provisional.
  \item Instruction semantics in this chapter are architectural unless explicitly described as pseudo-instructions.
  \item Opcode assignments are defined separately by the opcode map.
  \item Assembler syntax and pseudo-instruction expansion rules are defined by the toolchain specification.
\end{itemize}
