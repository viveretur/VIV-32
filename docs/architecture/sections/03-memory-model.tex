\section{Address Space}

\begin{itemize}
  \item VIV-32 uses a flat, byte-addressed 32-bit physical address space.
        Addresses are 32-bit unsigned values, and each byte is 8 bits.
  \item VIV-32 v\version{} does not support virtual memory, segmentation or
        paging.
\end{itemize}

\section{Endianness}

\begin{itemize}
  \item VIV-32 is big-endian. Multi-byte values are stored with the most
        significant byte at the lowest memory address. A 32-bit word value
        \code{0x12345678} stored at address \code{A} is represented as:
\end{itemize}

\begin{center}
\begin{tabular}{ll}
\hline
Address & Byte value \\
\hline
\code{A + 0} & \code{0x12} \\
\code{A + 1} & \code{0x34} \\
\code{A + 2} & \code{0x56} \\
\code{A + 3} & \code{0x78} \\
\hline
\end{tabular}
\end{center}

\section{Access Sizes}

VIV-32 supports 8-bit byte, 16-bit halfword and 32-bit word loads and stores.

\section{Alignment}

\begin{itemize}
  \item Byte accesses may occur at any address.
  \item Halfword accesses must be aligned to a 2-byte boundary.
  \item Word accesses must be aligned to a 4-byte boundary.
  \item Misaligned halfword or word accesses raise a
        \code{MisalignedAccessException}.
\end{itemize}

\section{Instruction Alignment}

\begin{itemize}
  \item VIV-32 instructions are 32 bits wide.
  \item Instruction fetch addresses must be word-aligned.
  \item Branch and jump targets must be word-aligned.
  \item Attempting to fetch an instruction from a misaligned address raises a\\
        \code{MisalignedFetchException}.
\end{itemize}

\section{Memory-Mapped I/O}

\begin{itemize}
  \item VIV-32 uses memory-mapped I/O (MMIO).
  \item Device registers occupy reserved physical address ranges.
  \item Exact device addresses are defined by the platform specification, not by
        the base ISA.
\end{itemize}

\section{Caching}

\begin{itemize}
  \item VIV-32 v\version{} defines no cache architecture. All memory accesses
        are treated as direct accesses to memory or memory-mapped devices.
  \item Cache behaviour, cache coherency, and memory barriers may be possible
        future extensions.
\end{itemize}

\section{Atomicity}

\begin{itemize}
  \item VIV-32 v\version{} does not define atomic read-modify-write memory
        instructions. Naturally aligned 8-, 16-, and 32-bit loads and stores are
        individually completed as single architectural memory operations.
  \item Multiprocessor atomicity, shared-memory locking, and inter-CPU memory
        ordering are deferred for future possible extension.
\end{itemize}

\section{Memory Ordering}

\begin{itemize}
\item A single processor observes its own memory operations in program order.
\item Implementations may execute operations internally in any manner provided the architectural
behaviour is equivalent to program-order execution.
\item VIV-32 v\version{} defines no multiprocessor memory consistency model.
\item Future versions may define memory barriers, atomic operations, and inter-processor
ordering rules.
\end{itemize}
